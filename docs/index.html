3개 매장의 주문 기록을 정리해 매출 기준을 세우고, 말로 물어도 같은 숫자를 돌려주는 Genie Agent를 만듭니다. 기초 과정은 12절까지 약 3시간이고, 심화(13~16절)까지 하면 약 5시간 15분 걸립니다.

오늘의 상황

강남점·판교점·해운대점을 운영하는 카페 본사입니다. 매장 POS에서 2주치(2026-07-01~07-14) 주문 기록이 CSV 여러 개로 나뉘어 들어옵니다. 이 데이터는 그대로 쓰기 어렵습니다.

  • 파일 사이에 중복 주문이 있고, 수량이 0 이하인 행, 비어 있는 할인율, 대소문자가 섞인 상태값도 있습니다.
  • 취소 주문을 넣을지, 할인을 뺄지에 따라 매출이 달라집니다. 기준이 없으면 사람마다 다른 숫자를 말합니다.
  • 현업은 "라떼 매출 알려줘"처럼 말로 묻고 싶어 합니다. 그런데 라떼는 카페라떼와 바닐라라떼 둘 다일 수 있고, "손님 수"는 고객 데이터가 없어 답할 수 없습니다.

오늘 할 일은 이 원천 CSV를 믿을 수 있는 매출 데이터로 정리하고, 계산 기준을 한 곳에 정의한 뒤, 그 기준으로 답하는 Agent를 만드는 것입니다. 답이 맞는지 재는 방법까지 함께 봅니다.

사전 조건과 화면 읽는 법

교육 전에 본인 계정으로 Databricks Free Edition에 가입하고 Workspace에 로그인해 둡니다. Catalog는 3절의 setup 노트북이 만듭니다. 그 과정에서 권한 오류가 나면 로그인한 계정이 본인 Free Edition Workspace인지 먼저 확인합니다.

필요한 기능과 권한 목록

Unity Catalog 사용, cafe_training에 대한 USE CATALOG, Schema 생성, Volume 생성·업로드, SQL Warehouse 사용, Serverless Lakeflow Pipeline, Gold 테이블 SELECT, cafe_hands_on Schema의 CREATE TABLE, Genie Agent 생성·편집.

13~16절 심화 실습은 Free Edition에서 필요한 기능과 모델을 쓸 수 있는지 강사가 미리 확인한 뒤 진행합니다.

왼쪽 메뉴

실습에서는 Workspace, Catalog, Jobs & Pipelines, Genie Agents, SQL Warehouses, Playground를 주로 씁니다. 아래는 2026-09-21에 찍은 Free Edition 홈 화면입니다.

헷갈리기 쉬운 것

  • Workspace는 코드와 노트북을 여는 곳이고, Catalog Explorer는 테이블·Metric View·Volume을 보는 곳입니다.
  • cafe_training.cafe_hands_on.gold_sales는 Catalog, Schema, Table 이름을 점으로 이은 것입니다.
  • /Workspace/...는 코드 경로, /Volumes/...는 업로드한 데이터 경로입니다.
  • <사용자 이메일>은 본인 로그인 이메일로 바꿉니다. 꺾쇠괄호는 빼고 입력합니다.
  • SQL 노트북에는 SQL Warehouse를, Python 노트북에는 Python을 실행할 수 있는 Compute를 연결합니다.
  • Pipeline은 Bronze·Silver·Gold 데이터를 만드는 흐름이고, Job은 Pipeline 실행과 검증의 순서를 관리합니다.

5-1무엇을 만드나

Volume의 CSV를 읽어 Bronze·Silver·Gold 데이터셋 7개를 만듭니다. Pipeline은 하나이고, 데이터셋을 만드는 SQL은 notebooks/01_cafe_medallion_pipeline.sql에 이미 있습니다. 이 파일을 Pipeline에 연결하기만 하면 됩니다.

SQL이 서로를 참조하는 관계를 보고 Lakeflow가 이 순서(DAG)를 알아서 짭니다. Silver와 Gold는 Materialized View입니다.

③Expectation의 역할 이해

silver_orders_clean에는 아래 품질 규칙이 선언되어 있습니다. quantity > 0을 만족하지 않는 행은 Silver 결과에서 빠집니다.

silver_orders_clean의 품질 규칙
CONSTRAINT positive_quantity
  EXPECT (quantity > 0) ON VIOLATION DROP ROW

세 가지는 빠지는 곳이 다릅니다.

  • 중복 2행은 SQL의 ROW_NUMBER()로 지웁니다.
  • 수량 오류 2행은 위 Expectation에 걸려 Silver에서 빠집니다.
  • 취소 30행은 Silver에는 남아 있고 Gold에서 뺍니다.

# 카페 매출 Genie Agent 지침

## 목적과 범위

- 카페 매출 데이터를 사용해 사용자의 질문에 근거 있는 분석 결과를 제공한다.
- 분석 대상은 연결된 Metric View에 정의된 필드, 측정값, 설명, 동의어로 제한한다.
- 데이터 자산에 없는 컬럼, 지표, 고객 정보는 임의로 만들지 않는다.
- 응답은 한국어 존댓말로 작성한다.

## 질문 해석 규칙

- 사용자의 표현을 Metric View의 표시명, 설명, 동의어와 연결해 해석한다.
- 비슷한 개념이라도 의미가 다른 필드와 측정값은 구분한다. 예: 금액과 수량, 주문 건수와 판매 수량, 총액과 순액.
- 사용자가 지표를 명확히 지정하지 않으면 Metric View에 정의된 기본 의미를 사용하고, 응답에 적용한 지표를 표시한다.
- 기간, 비교 기준, 집계 수준 또는 정렬 기준이 결과에 큰 영향을 주는데 질문에 포함되지 않았다면 짧게 되묻는다.
- 하나의 표현이 여러 필드나 지표로 해석될 수 있으면 가능한 선택지를 제시하고 사용자의 확인을 받는다.

## 데이터 및 계산 규칙

- Metric View에 정의된 측정값과 차원을 우선 사용한다.
- 이미 정의된 측정값이 있는 경우 원시 컬럼을 임의로 다시 계산하지 않는다.
- 데이터에 없는 정보나 근거 없는 원인을 추정하지 않는다.
- 요청한 데이터가 없으면 제공할 수 없다고 명확히 설명하고, 대신 사용할 수 있는 관련 지표나 차원을 제안한다.
- 필터와 기간을 적용한 경우 실제 적용 조건을 응답에 명시한다.

## 응답 형식

- 수치에는 적절한 단위와 측정값 이름을 표시한다.
- 비교나 추이 분석은 가능한 경우 표로 제시하고, 정렬 기준과 기간을 함께 표시한다.
- 결과 뒤에 핵심 해석을 간결하게 덧붙인다.
- 답변은 데이터로 확인할 수 있는 사실과 해석을 구분한다.

12Genie 품질 개선

Benchmark에서 틀린 문항이 나왔을 때 어디를 고칠지 정하는 방법입니다.

12-1기능별 역할

Genie 품질에 관여하는 구성 요소는 다섯 가지입니다. Metric View, Example Query, Instruction은 Genie가 답을 만들 때 참고하고, Benchmark와 Monitor는 그 답이 맞는지 확인할 때 씁니다.

구성 요소쓰임넣을 내용
Metric View답을 만들 때 참고필드·측정값의 의미, 표시명, 설명, 동의어, 포맷, 공통 업무 규칙
Example Query답을 만들 때 참고자주 쓰는 질문과 검증된 SQL 패턴
Instruction답을 만들 때 참고여러 질문에 공통으로 적용되는 해석·응답 원칙
Benchmark답을 확인정확도와 회귀 테스트를 위한 질문·SQL Answer·Evaluation note
Monitor답을 확인실제 질문, 생성 SQL, 피드백, 반복 오류

12-2권장 개선 순서

무엇을 더했을 때 정확도가 올랐는지 알 수 있도록, 아무것도 더하지 않은 상태의 점수부터 재 두고 하나씩 더해 갑니다.

  1. Genie에 Metric View만 연결하고 지침·예제는 넣지 않은 상태로 Benchmark를 돌립니다. 이때 나온 Accuracy가 비교의 출발점입니다.
  2. Metric View의 필드와 측정값에 표시명·설명·동의어·포맷을 채웁니다.
  3. 자주 나오는 질문은 검증된 SQL과 함께 Example Query로 넣습니다.
  4. 같은 Benchmark를 다시 돌려 1번의 Accuracy와 비교합니다.
  5. 틀린 문항은 Genie가 만든 SQL과 SQL Answer를 나란히 놓고 봅니다.
  6. 원인에 맞는 구성 요소 하나만 고칩니다.
  7. 같은 문항을 다시 돌리고, 전에 맞던 문항이 틀리지 않았는지도 봅니다.

12-3실패 원인별 수정 위치

여러 곳을 한꺼번에 고치면 무엇이 효과가 있었는지 알 수 없습니다. 원인에 맞는 곳 한 군데만 고치고 같은 Benchmark를 다시 돌립니다.

이런 문제가 보이면먼저 고칠 곳
용어가 엉뚱한 필드나 측정값으로 연결됨Metric View의 표시명·설명·동의어
자주 나오는 질문 유형의 SQL이 들쭉날쭉함Example Query
여러 질문에 공통으로 필요한 해석 규칙이 없음Instruction
정답 SQL이나 채점 기준 자체가 틀림Benchmark의 SQL Answer · Evaluation note
실제 사용자 질문에서 같은 오류가 반복됨Monitor에서 원인을 보고 위 넷 중 하나

12-4생성 SQL 검토와 Add as instruction

실패한 응답에서 … → Show code를 누르고 생성 SQL, SQL Answer, 실행 결과를 나란히 봅니다.

12-5Instruction 작성 원칙

Instruction 예시

# Cafe Supervisor Agent 시스템 지침

당신은 카페 운영 담당자를 위한 한국어 분석 어시스턴트입니다. 구조화된 매출 분석은 Genie Agent에 위임하고, 회사 용어·약어·다의어는 AI Search 용어집에서 먼저 확인합니다.

## Tool routing

1. 표준 필드와 표준 지표로 답할 수 있는 정량 질문은 바로 Genie Agent를 호출합니다.
2. `아메`, `피크타임`, `라떼`, `손님수`처럼 별칭·업무용어·다의어가 포함된 질문은 AI Search를 먼저 호출합니다.
3. AI Search 결과가 하나의 표준 필드나 지표로 확정되면 그 정의를 반영하여 Genie Agent를 호출합니다.
4. AI Search 결과가 명확화 질문을 요구하면 사용자에게 먼저 되묻고, 답을 받기 전에는 Genie Agent를 호출하지 않습니다.
5. 직접 SQL을 작성하거나 숫자를 추측하지 않습니다. 모든 정량 수치는 Genie 결과를 근거로 답합니다.

## Business rules

- `매출`의 기본값은 완료 주문의 할인 후 `순매출`입니다.
- `인기메뉴`는 매출 기준과 판매수량 기준 중 하나를 사용자에게 확인합니다.
- `라떼`는 카페라떼와 바닐라라떼 중 어느 상품인지 확인합니다.
- 고객 식별자와 방문객 데이터가 없으므로 `손님수`를 직접 계산하지 않습니다. 주문수 또는 판매수량을 대체 지표로 제안합니다.
- `최근`은 데이터 최대 일자를 기준으로 직전 7일이며 실제 적용 기간을 응답에 적습니다.

## Answer style

- 한국어 존댓말로 간결하게 답합니다.
- 표 또는 숫자 뒤에 사용한 기간·지표·필터를 짧게 명시합니다.
- 도구 결과가 없거나 실패하면 실패 원인을 알리고 필요한 조건을 요청합니다.
- 데이터에 없는 원인이나 고객 행동을 추정하지 않습니다.
  1. 아래 네 질문을 각각 새 대화에서 물어봅니다. 답뿐 아니라 어떤 도구를 어떤 순서로 불렀는지도 봅니다.
질문기대하는 도구 흐름기대 결과
매장별 순매출을 비교해줘Genie매장별 매출 표
아메 매출 알려줘AI Search→Genie아메리카노로 해석한 매출
