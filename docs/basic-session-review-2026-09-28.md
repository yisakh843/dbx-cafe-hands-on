# 기초 세션 검토 · 2026-09-28

현재 분량을 모두 수행하는 초심자 수업은 **약 3시간 30분~4시간**, 편성은 **4시간**을 권장한다. 3시간으로 운영하려면 반복 입력 분량과 선택 실습을 줄여야 한다. 아래 시간은 실제 완주 측정값이 아니라, 가이드의 작업 수·설명·결과 확인·대기와 수강자 지원을 합산한 추정이다.

검토 대상은 배포된 HTML 가이드의 0~12절, 로컬 SQL과 CSV, Databricks 공식 Benchmark 문서다. 열린 Databricks 홈에서 Free Edition 및 메뉴를 확인했으나, 콘솔에 자동화 브라우저 제어를 지원하지 않는다는 안내가 표시되었다. 따라서 이번 검토에서는 새 리소스 생성, Pipeline/Job 실행, Genie 질문과 Benchmark 실행을 완료하지 않았다. SQL의 Databricks 실행 호환성, 현재 설정 화면의 모든 버튼 위치, 실제 대기 시간은 미검증이다. 기존 가이드·노트북에 있던 작업 중 변경은 수정하지 않았다.

## 확인한 정상 부분

- CSV → Bronze/Silver/Gold → Job → Metric View → Genie → 평가라는 전체 이야기와 산출물 연결은 자연스럽다.
- Workspace 경로와 Volume 경로, SQL 노트북과 Pipeline 소스의 실행 방법을 구분한 안내가 유용하다.
- Git folder와 PC ZIP이 각각 왜 필요한지, 업로드 목적지가 어디인지, 단계별 완료 상태가 무엇인지 설명되어 있다.
- HTML에는 Example Query와 Benchmark의 복사용 내용이 있어 CSV에서 여러 줄 SQL을 직접 꺼내는 수고를 줄인다.
- 03 실행 후 02를 Run all 하면 설명과 동의어가 사라진다는 주의도 이미 있다.

샘플 CSV를 Python 표준 라이브러리로 읽어 제공 SQL의 중복 제거·타입 정리·필터·결합 규칙을 재현했다. 이는 샘플 정답 검증이며 Spark 실행 검증은 아니다.

## 먼저 보완할 부분

### 1. 개선 전 점수를 재기 전에 최적화가 끝난다

**위치:** 7~12절, `docs/index.html:1521`.

현재 순서는 7절 기본 Metric View → 8절 최적화 정의 → 9절 지침 → 10절 예제 6개 → 11절 첫 평가다. 그런데 12-2는 지침·예제 없는 상태의 점수부터 비교하라고 한다. 수강자는 이 지점에서 앞 단계로 돌아가 설정을 지워야 하는지 혼란스럽고, 실제로 최초 상태의 Accuracy가 없다.

**권장:** 기초에서는 11절 결과를 “현재 구성의 첫 평가”로 명명하고, 실패 하나를 수정한 전후만 비교한다. 지침 없는 최초 상태부터의 비교는 별도 선택 실험으로 명시한다. 최초 상태부터 비교하는 것이 필수 목표라면 8절과 9절 지침·10절 예제 등록을 첫 Benchmark 뒤로 이동하고, 첫 평가 시간을 추가 배정한다. 여러 요소를 한꺼번에 적용한 뒤 특정 요소 때문에 개선되었다고 설명하지 않는다.

### 2. B012는 Agent에게 알려주지 않은 업무 규칙을 채점한다

**위치:** `resources/genie_instructions.md:15`, `docs/index.html:1466`, `sample_data/support/genie_benchmarks.csv`.

지침은 기간이 모호하면 되묻도록 한다. B012의 질문은 “최근 매출 추이를 보여줘”인데, 채점 기준은 데이터 최대일 2026-07-14 기준 최근 7일을 바로 사용하라는 것이다. 이 7일 규칙은 기본/최적화 Metric View와 Genie 지침에 없고, 이후 심화에서 쓰는 용어집에 있다. Volume에 용어집을 올리는 것만으로 기초 Genie에 그 내용이 전달되지는 않는다.

Evaluation note는 답변 생성 지침이 아니라 채점자에게 전달하는 기준이다. [공식 Benchmark 문서](https://docs.databricks.com/aws/en/genie-agents/monitor#add-benchmark-questions).

**권장:** 기초의 되묻기 원칙을 유지하려면 B012 평가 기준을 “최근의 기간과 기준일을 확인한다”로 바꾼다. 최근 7일을 바로 적용하는 것이 목표라면 업무 규칙을 Agent의 지침/메타데이터에도 명시한다. 또는 B012를 의도적인 불일치 찾기 실습으로 밝히고 12절에서 함께 고친다. 현재처럼 숨은 규칙을 모르는 정상 응답을 단순 실패로 취급하지 않는다.

### 3. Benchmark 실행 경로는 모드 선택을 먼저 안내해야 한다

**위치:** 11-3, `docs/index.html:1474`.

가이드는 `B001~B008 선택 → Run selected → Mode: Chat` 순서다. 현재 공식 문서는 Benchmarks 오른쪽 위에서 모드를 고르며 그 모드가 실행 전체에 적용된다고 안내한다. 잘못된 모드로 실행하면 특히 SQL Answer가 없는 B009~B012에서 혼란이 생긴다.

**권장:** `Mode: Chat 확인 → 해당 8문항 선택 → Run selected`와 `Mode: Agent 확인 → 해당 4문항 선택 → Run selected`로 쓴다. 첫 문항 입력 창, 모드 선택 위치, 평가 상세 화면의 캡처를 추가한다. B001 같은 ID는 교재상의 식별자이고 현재 입력 절차에는 ID 등록이 없으므로, 목록에서 질문 문구로 찾는다는 설명도 필요하다. 실제 워크스페이스의 버튼 위치는 수동 재확인 대상이다. [공식 모드 안내](https://docs.databricks.com/aws/en/genie-agents/monitor#benchmarks).

### 4. SQL이 없는 실패 응답에는 Show code가 없을 수 있다

**위치:** 12-4, `docs/index.html:1546`.

“실패한 응답에서 Show code → SQL Answer와 비교 → Add as instruction”은 SQL을 생성한 문항에 맞는 절차다. 되묻기·지원 범위를 평가하는 Agent 문항은 SQL과 SQL Answer가 없을 수 있다. 또 Manual Review가 남으면 Accuracy 확인 단계에서 멈출 수 있다.

**권장:** 숫자/SQL 실패는 생성 SQL·정답 SQL·결과를 비교하고, 명확화/행동 실패는 응답 문장·Evaluation note·지침을 비교하는 두 경로를 제시한다. Manual Review에서는 평가 상세의 응답을 읽고 Good/Bad를 판정하는 예시 하나를 넣는다. 판정만 바꾼 것은 Agent를 개선한 것이 아님도 설명한다. [공식 평가 상세 안내](https://docs.databricks.com/aws/en/genie-agents/monitor#review-individual-evaluations).

### 5. “세 질문 모두 되묻기 성공”을 다음 단계의 필수 조건으로 두기 어렵다

**위치:** 10절 마지막 체크, `docs/index.html`의 `모호한 질문 세 개에서 Genie가 되물었다`.

설정을 올바르게 했어도 응답은 달라질 수 있다. 세 문항 모두 기대대로 나와야만 완료로 보는 체크는 수강자가 계속 재시도하도록 만든다. 또한 같은 대화에서 여러 질문을 이어서 하면 앞의 문맥이 다음 답에 영향을 줄 수 있다. Benchmark 질문은 각각 새 대화로 처리된다.

**권장:** “세 질문을 각각 새 대화에서 테스트하고, 기대와 다른 반응을 기록했다”로 바꾼다. 실패는 11~12절의 평가·개선 재료로 가져간다. 실행 오류로 답이 안 나온 경우와 의미를 잘못 해석한 경우도 구분한다. [공식 테스트 및 대화 문맥 안내](https://docs.databricks.com/aws/en/genie-agents/monitor#benchmarks).

## 소요 시간 재산정

전제: 계정 가입·로그인은 완료, SQL/Databricks 초심자, 강사와 함께 진행, 18개 항목 수동 등록, 짧은 설명과 확인 포함. 서비스 장애·사용량 제한·장시간 인증 문제는 제외했다. 실행 대기는 일부 설명과 겹쳐 진행하는 것으로 본다.

| 구간 | 예상 |
|---|---:|
| 상황·화면·이름 규칙 | 10~15분 |
| Git/ZIP·Setup·CSV 업로드 | 35~45분 |
| Pipeline 설정·첫 실행·정제 이해 | 25~30분 |
| Job 두 Task·검증 결과 | 15~20분 |
| Metric View 기본/최적화·조회 | 20~25분 |
| Genie 생성·지침·예제 6개·채팅 | 25~35분 |
| Benchmark 12개 등록·두 모드 평가 | 30~40분 |
| Monitor·실패 원인·제한된 재평가 | 15~20분 |
| 휴식·질문·진도 회복 여유 | 20~30분 |
| 합계 | **195~260분 (3시간 15분~4시간 20분)** |

일반적인 편성 예상은 3시간 30분~4시간, 안전한 수업 슬롯은 4시간이다. SQL이나 화면 조작이 익숙한 참가자는 더 빨리 끝날 수 있다. 전체 Benchmark를 여러 차례 재실행하거나 최초 상태부터 단계별 효과를 비교하면 위 범위를 넘길 수 있다.

기존 설계의 기초 180분은 소개 15 + 데이터 엔지니어링 55 + Metric View 30 + Genie 65 + 휴식 15다. Git/ZIP·Catalog·업로드 준비가 독립적으로 배정되어 있지 않다. 이를 데이터 엔지니어링 55분 안에 넣으면 Pipeline/Job 설명과 수강자 지원의 여유가 부족해진다. 문서에 있는 Job의 41초·23초는 촬영 당시 실행 시간이며 참가자의 설정·대기·결과 확인 시간을 대표하지 않는다.

### 3시간을 유지하는 운영안

가입·로그인과 ZIP 다운로드·압축 해제는 사전 과제로 둔다. 본 수업은 아래처럼 범위를 명시한다.

| 경과 시간 | 진행 내용 |
|---|---|
| 00:00~00:10 | 시나리오와 오늘의 산출물 |
| 00:10~00:40 | Git folder·Setup·기초 CSV 5개 업로드 |
| 00:40~01:05 | Pipeline 실행·정제 숫자 확인 |
| 01:05~01:20 | Job 두 Task와 PASS 확인 |
| 01:20~01:30 | 휴식 |
| 01:30~01:50 | Metric View와 의미 정보 |
| 01:50~02:15 | Genie·지침·대표 예제 3개 |
| 02:15~02:40 | Chat 4개·Agent 2개 Benchmark 및 결과 |
| 02:40~02:55 | 실패 하나 분석·수정·재평가 또는 강사 사례 |
| 02:55~03:00 | 완료 확인·마무리 |

필수 예제는 E001/E002/E003, 필수 Chat 문항은 B001/B002/B003/B008, 필수 Agent 문항은 B009/B010으로 시작할 수 있다. 나머지는 선택 과제로 표시하고 체크리스트도 축소 범위와 맞춘다. B012는 위의 규칙 불일치를 해결한 후 선택 과제로 넣는다. 수강자별 실패가 없으면 일부러 오류를 만들지 않고 강사가 준비한 실패 응답으로 개선 과정을 설명한다.

3시간판에서도 지연이 누적되면 반복 등록보다 원인 분석과 결과 해석 시간을 지키는 것이 좋다. 5절 완료와 9절 완료 시점에 전체 진도를 확인한다.
